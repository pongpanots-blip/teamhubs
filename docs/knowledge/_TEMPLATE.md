# <ชื่อเอกสาร เช่น "Payment Gateway Integration">

หนึ่งย่อหน้าสั้น ๆ สรุปว่าเอกสารนี้พูดถึงอะไร ใครควรอ่าน — ระบบใช้ H1 นี้เป็น title ของเอกสาร

## บริบท / ทำไมต้องมี

อธิบายเหตุผล ที่มา หรือปัญหาที่เอกสารนี้ตอบ ไม่ต้องยาว 2-3 ประโยคพอ

## รายละเอียด

เนื้อหาหลัก แบ่งเป็นย่อหน้าสั้น ๆ (ระบบจะ chunk ตามย่อหน้า ~1200 ตัวอักษร/chunk
ก่อน embed) — เขียนแต่ละย่อหน้าให้ "ยืนเดี่ยวได้" คือถ้าดึงย่อหน้านี้ออกมา
เดี่ยว ๆ ตอน RAG แล้วยังเข้าใจได้ ไม่ต้องอ้างอิงย่อหน้าก่อนหน้า

หลีกเลี่ยงการ dump table/JSON ยาว ๆ เป็นก้อนเดียว ถ้ามีหลายรายการให้แยกเป็น
bullet หรือย่อหน้าแยกกัน

## กฎ / ข้อจำกัดทางธุรกิจ (ถ้ามี)

- ระบุ business rule ที่ต้องรู้ เช่น เงื่อนไข validation, edge case,
  ค่า default, ใครมีสิทธิ์ทำอะไร

## อ้างอิง (ถ้ามี)

ลิงก์ไปเอกสาร ticket หรือระบบภายนอกที่เกี่ยวข้อง
